# MC Corporate Admin

Это учебный проект админ-панели корпоративного сервиса. Я сделал его на Java и Spring Boot, чтобы потренироваться в настройке безопасности, ролей и прав доступа.

## Что умеет проект

- авторизация по логину и паролю;
- управление пользователями: создание, редактирование, блокировка и удаление;
- создание ролей и выбор разрешений для каждой роли;
- ограничение страниц и действий по правам доступа;
- журнал основных действий администратора;
- адаптивный интерфейс на Thymeleaf;
- хранение данных в локальной базе H2.

## Скриншоты и роли

После первого запуска создаются три роли:

| Роль | Возможности |
|---|---|
| `ADMIN` | Полный доступ |
| `MANAGER` | Просмотр и управление пользователями |
| `AUDITOR` | Просмотр пользователей, ролей и аудита |

Тестовый администратор: `admin` / `admin123`.

> Пароль нужен только для локального демонстрационного запуска. В реальном проекте его нужно задавать через переменные окружения.

## Стек

- Java 17
- Spring Boot 4
- Spring Security
- Spring Data JPA
- Thymeleaf
- H2 Database
- Maven
- JUnit 5 и Mockito

## Как запустить

Нужна установленная Java 17 или новее.

```powershell
mvn spring-boot:run
```

Потом открыть: <http://localhost:8080>

Проверка тестов:

```bash
mvn test
```

## Структура

```text
domain/      сущности и разрешения
repository/  работа с базой данных
service/     бизнес-логика и интерфейсы
web/         контроллеры и формы
config/      безопасность и начальные данные
```

## SOLID и паттерны

- **SRP**: контроллеры отвечают за HTTP, сервисы — за логику, репозитории — за данные.
- **DIP**: контроллеры зависят от интерфейсов `UserManagementService`, `RoleManagementService` и `AuditService`.
- **Strategy**: `AuditService` можно заменить другой реализацией, например отправкой событий во внешний сервис.
- **Repository**: доступ к данным скрыт за Spring Data репозиториями.
- **Dependency Injection**: зависимости передаются через конструкторы.
- **MVC**: модели, контроллеры и HTML-представления разделены.

## Важное

База создаётся в папке `data` и не попадает в Git. CSRF-защита Spring Security включена по умолчанию, пароли хранятся как BCrypt-хэши.
